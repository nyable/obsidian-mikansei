# 文档索引

用户从 [项目 README](../README.md) 开始；开发者与 AI Agent 先读 [AGENTS.md](../AGENTS.md)，再按当前任务查阅，避免把所有历史记录当作必读上下文。

## 按任务阅读

- **使用与设置**：[使用指南](./USER-GUIDE.md)。详细操作、限制与加载排查。
- **定位模块与数据流**：[架构](./ARCHITECTURE.md)。职责、持久化、权限边界及源码入口。
- **安装开发环境**：[开发环境与本地调试](./DEVELOPMENT.md)。命令、构建和测试库。
- **修改代码**：[开发规范与踩坑](./CONVENTIONS.md)。必须遵守的约束、原因和验证线索。
- **增加回归或验收**：[测试与验收](./TESTING.md)。自动化覆盖边界、宿主及移动端清单。
- **准备发布**：[发布流程](./RELEASE.md)。版本、CI、附件核对及发布前检查。
- **查特定时间点结论**：[发布与验证记录](./RELEASE-VALIDATION.md)。历史证据、未验证范围和待确认事项；不是当前状态保证。

## 文档职责与事实来源

- README 只承载简单介绍、安装和最小使用说明，不放技术栈、长篇功能清单、问题反馈或发布状态。
- `AGENTS.md` 是硬性规则摘要与任务导航；完整规则、理由和踩坑集中于 `CONVENTIONS.md`。
- 用户可见行为集中于 `USER-GUIDE.md`；模块职责集中于 `ARCHITECTURE.md`，不要复制整份源码目录。
- 环境与命令以 `.node-version`、`package.json` 为事实来源；设置类型、默认值和加载校验以 `src/settings/types.ts` 为实现入口。
- 规则表达预期约束，测试提供行为证据；若实现与文档冲突，先结合需求和历史确认，不默认以代码覆盖规范。
- 阶段性结果必须标注日期、验证对象和范围。尚未决定的策略不能写成已经生效的规则。

## 维护方式

修改相关行为时，在同一改动中更新对应说明、翻译和回归测试；只有影响基础安装或最小使用流程时才扩充 README。链接优先使用仓库相对路径，示例只使用脱敏或合成数据。完整检查清单见 [文档同步](./CONVENTIONS.md#文档同步)。
