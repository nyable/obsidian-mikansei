# 开发规范与踩坑

本文是详细开发规范的维护位置，[AGENTS.md](../AGENTS.md) 只保留硬性规则摘要与导航。修改行为时先确认需求、用户说明和测试证据，不把“奇怪行为”直接当成 Bug，也不默认以代码覆盖文档。

## 设置与高频交互

**约束**：输入、拖拽等高频 `onChange` 只更新本地草稿，禁止直接反复写 `plugin.settings` 并 `saveSettings()`。使用本地草稿、防抖提交，以及交互结束 / 失焦 / 关闭 / 卸载时 flush；无效草稿不提交。

**踩坑**：逐帧写盘会卡顿；`value || default` 会吞掉合法的 `0`；仅监听 prop 值变化不能识别“恢复到相同默认值”，旧计时器或卸载 flush 可能覆盖重置结果。

- 参考 `src/settings/components/useDebouncedDraft.ts` 与 `ColorInput.tsx`，不要再实现不一致的颜色 / 文本提交机制。
- 外部重置优先于旧草稿，使用代次或等效失效机制阻止旧回调提交。
- `src/settings/types.ts` 的 `parseSettings` 是持久化边界：校验布尔值、枚举、颜色、标识符和数字范围。TypeScript 类型不能校验 `data.json`，字符串 `"false"` 不能当成布尔关闭值。
- 设置提交后调用 `applySettings()` 按需重配置，`saveSettings()` 使用快照串行保存并处理失败。失败保留会话值并提供重试，不能同时提示“已保存 / 恢复成功”。
- 长期回调读取最新设置，不长期捕获旧开关。确需重载的设置须在中英文文案与用户说明中标注。
- 无关设置不得清理解锁会话；更改加密开关 / 围栏标识符会清理会话，但不自动迁移笔记。
- 设置面板每功能一个 tab，恢复默认需确认。交互控件使用有名称与状态的可访问原生控件，不能只有鼠标可用。

**验证**：`tests/settings-runtime.test.mjs`；检查高频输入、零值、无效值、同值重置、关闭 / 卸载 flush、失败重试及动态注册。

## 异步写入与目标保护

**约束**：异步开始前捕获具体文件、目标内容与位置；完成后重新校验文件身份、内容、功能状态和生命周期，涉及选区时也校验选区。不能使用请求完成时的新光标覆盖原目标；冲突时拒绝写入或保留原内容。

**踩坑**：开头检查开关并不能保护密码计算完成后的写入；同路径文件可能已经是新对象；发起 `Vault.process` 后，宿主仍可能排队到稍后才调用转换函数。

- 加密写回统一经 `blockStorage.ts`：优先使用有效 source 编辑器，尊重未保存文本并保留撤销；否则用 `Vault.process`。多编辑器缓冲区不一致时拒绝猜测。
- 计算前后、写入前及 `Vault.process` 回调内校验有效期。文件被替代、排队期间打开 source 编辑器时拒绝后台写入。
- 命令按文件阻止重复操作；关闭加密、改变标识符或卸载会取消密码弹窗与待处理操作。切换笔记不会改变捕获目标。
- 链接增强先校验 URL 再阻止原生粘贴；先插入默认链接，再尝试更新标题。笔记 / 选区 / 功能状态变化时放弃更新。
- 取消信号只是失效与清理机制，不等于能中断 Web Crypto 或撤回已发出的宿主磁盘操作。

**参考与验证**：`blockContent.ts`、`blockStorage.ts`、`cryptoCommands.ts`、`linkPasteEnhancer.ts`；测试见 `crypto-commands.test.mjs`、`crypto-block.test.mjs` 和 `runtime-regressions.test.mjs`。

## 密文与文本兼容

**约束**：`src/features/crypto-block/crypto.ts` 的算法、参数与打包格式必须向后兼容，不随意更改。新功能经 service 层适配，不能默默重写用户历史数据。

**踩坑**：按 `\n` 分行会把 CRLF 的结构性 `\r` 留在最后一行；加密后写回又加 CRLF 会形成 `\r\r\n`。无条件 `trim()` 会删除用户真实数据，不是兼容修复。

- 分离围栏结构分隔符与正文，保留内部换行、尾部空行及历史字面回车。
- 解析时复用原始切片，不能对每个候选重新 split 整篇文档；歧义 / 不支持嵌套或缩进时拒绝写回，不改成猜测目标。
- 格式异常、认证失败、环境能力异常需合理区分；缺少 Web Crypto 不能误报为密码错误。
- 渲染语言是未认证公开元数据。合法密文不代表其渲染来源可信，不可未经决策就更改信任策略或密文格式。

**验证**：LF / CRLF 加解密完整往返、空块、尾部空行、历史字段、字面回车、错误密码、缺失能力、重复块与较大文档。现有 service 与 legacy 的互读测试不是固定历史 fixture 的替代品。

## 移动端与构建边界

**约束**：`src/` 在 Obsidian WebView 运行，不直接使用 Node.js / Electron 模块或 Node 全局变量；脚本和测试不受此运行时限制。网络 / 文件访问优先使用浏览器或 Obsidian API。

**踩坑**：Vite lib 模式不会自动替换 `process.env.NODE_ENV`，桌面可以加载不代表移动端可以加载；依赖树中的 Node 入口也不一定进入实际产物，需检查打包可达性。

- 保留 `vite.config.mts` 显式 `define`，开发 / 生产分别替换为对应字面量；不能给手机注入假 `process` 掩盖错误。
- 保持 CJS 单入口与三个必需产物。Obsidian 提供的 CodeMirror / Lezer 模块保持外部依赖，避免重复运行时实例。
- 新依赖核对浏览器入口、间接依赖和实际产物；新增外部模块核对最低宿主及移动端可用性，不能只扩大测试允许列表。
- ESLint 导入 / 全局限制不是沙箱，不能代替动态引用与全局属性访问审查。
- 最新 `obsidian` 类型定义不能证明旧宿主支持。新 API 需兼容回退或明确调整 `manifest.json`、当前版本映射及用户要求；不要未经确认改写历史映射和 tag。

**验证**：`project-constraints.test.mjs`、`mobile-bundle.test.mjs`，以及最低宿主 / 真机验收。开发与生产产物都必须通过无 Node 全局变量加载测试。

## 生命周期与状态隔离

**约束**：事件、计时器、React 树、渲染处理器、宿主子组件、全局样式都必须有可重复调用的清理路径。重复启停不得重复注册，异步完成不得复活已卸载视图或继续发起失效写入。

- CodeMirror 使用已注册的可变扩展数组重配置并调用 `workspace.updateOptions()`；加密处理器 dispose 注销处理器并清理子组件。
- 编辑器位置按编辑器隔离，密码与明文会话按当前视图隔离，不使用全局“上一次匹配”或共享密码。
- 预览使用独立组件管理第三方资源，迟到的处理器也需清理；已发生的第三方外部副作用无法撤销。
- 内存草稿、busy 期间暂停自动锁定、零超时跳过请求、标识符不自动迁移均有明确设计依据，不能借修 Bug 擅自改变。

**参考与验证**：`ReactRenderChild.ts`、`codeBlockProcessor.ts`、`previewRendering.ts`、`CryptoEditModal.tsx`；`crypto-interactions.test.mjs`、`crypto-edit-modal.test.mjs`、`settings-runtime.test.mjs`。真实宿主验收不可省略。

## i18n

所有面向用户的文案走 `src/i18n`，中文与英文键集保持一致。使用既有类型增强与键集测试，不在组件中硬编码提示，也不把内部错误或敏感数据直接暴露给用户。

## 隐私与脱敏

- 文档、日志、测试样本和问题反馈不得包含真实密码、明文草稿、凭证、Token、Cookie、私钥、真实笔记内容或可关联用户的密文。
- 不记录本机绝对路径、系统用户名、私人笔记库名、内网主机、设备序列号、会话标识或带签名 / 敏感参数的 URL。
- 使用仓库相对路径、`example.com`、通用文件名与人工生成的测试内容。不要复制真实 `data.json`、配置目录或完整控制台日志作为示例。
- 截图清除侧边栏、笔记名、账号和系统路径；验收记录只保留必要的平台 / 系统 / 宿主版本与结果。
- 公开项目链接与必要署名不因包含公开账号名就自动判定为隐私。发现疑似泄露时先阻止扩散；确认泄露凭证需撤销 / 轮换，单删文档不能消除历史泄露，不擅自重写 Git 历史。

## 文档同步

- 用户行为 → 更新 `USER-GUIDE.md` 与相关翻译；只有基本安装 / 最小使用改变时更新项目 README。
- 模块职责 / 数据边界 → 更新 `ARCHITECTURE.md`；规则 / 踩坑 → 更新本文，必要时同步 `AGENTS.md` 摘要。
- 环境 / 命令 → 更新 `DEVELOPMENT.md`；测试方法 → 更新 `TESTING.md`；发布流程 → 更新 `RELEASE.md`。
- 特定时间点结果 → 更新 `RELEASE-VALIDATION.md`，注明验证对象、证据与未验证范围；不放进 README，也不冒充实时状态。
- 设置、依赖、命令和版本数字以代码 / 配置为事实来源，不重复维护完整表格；用户必需的默认值若写入指南，变更时必须同步。
- 文档应按任务可查阅。使用稳定标题和相对链接，迁移时修复所有引用；不写死行号、测试总数、产物大小和机器路径。
- 每次变更检查文档一致性、隐私与链接。提交前执行 `pnpm check` 和 `git diff --check`；不得通过删测试、放宽规则、篡改兼容要求掩盖失败。
