# 发布与验证记录

本文件记录特定时间点的发布问题和验证范围，不代表后续版本的实时状态。通用要求见 [发布流程](./RELEASE.md) 与 [测试验收](./TESTING.md)；README 仅保留简单用户介绍和使用说明。

## 2026-10-28：审计修复后的记录

验证对象为当时的审计修复工作区，版本字段仍为 `2.0.0`；本条未绑定准确构建提交和产物哈希，不能作为其他提交或公开附件的通过证明。下列结果来自当次检查，不是本文件被阅读时的实时状态。

### 公开附件问题

审计时检查的 [Release 2.0.0](https://github.com/nyable/obsidian-mikansei/releases/tag/2.0.0) 的 `main.js` 仍含旧的 Node 全局变量引用，在无 `process` 的模拟环境加载会失败。当前源码的修复并未更新这些公开附件，本轮未创建新版本、tag 或 Release。

在包含修复的新版本发布前，可从包含修复的源码自行构建；不能把旧附件视为已修复版本。发布时应记录构建提交，下载实际附件并比对 SHA-256，确认上传的是预期产物，不随意移动已发布 tag。

### 已执行验证

- `pnpm check` 通过，包含 Lint、回归测试、TypeScript 检查及生产构建。
- 开发、生产构建通过无 Node 全局变量的模拟加载测试。
- `git diff --check` 通过。
- 本地发布检查通过，但仅证明元数据一致及三个必需文件非空，不证明源码身份或远端附件正确。

### 尚未验证

- 旧宿主预览已增加 `renderMarkdown` 回退，并通过 API 替身测试，但未完成最低支持版本的真实 Obsidian 验收。
- Android / iOS 真机与真实宿主交互尚未验证；模拟加载不能作为真机兼容结论。

后续发布须补充实际构建提交、附件核对结果及设备 / 系统 / Obsidian 版本，未执行的验收不得标记为通过。

## 后续验证与待确认策略

以下为该次审计留下的事项，不是已经完成的修复或已批准的新需求：

- **真实集成**：补真实 React DOM、Obsidian onload / 卸载、最低宿主及 Android / iOS 验收；核对预览高度即时生效和 Live Preview 注册边界。
- **兼容证据**：增加可公开复现的固定历史密文样本，不使用真实私人密文。
- **自动锁定**：现有 busy 等待期间暂停锁定；非编辑弹窗和切后台是否应改变该策略，需要产品确认。
- **预览信任**：渲染语言未认证，可执行式第三方预览是否需要额外确认或安全回退，需要决策；不擅自改变旧格式。
- **网络资源**：标题请求的响应大小、并发、缓存和内网 / 隐私策略尚未收敛；现有 API 超时不能取消请求。
- **依赖维护**：当次安全扫描发现依赖告警，未执行升级。需重新扫描并按产物 / 开发工具可达性评估，不把依赖树告警直接当成插件可利用漏洞；定期 npm 更新机制仍需处理。
- **历史发布**：旧版本映射与 tag 的异常需核对实际附件，不通过文档整理重写历史。

执行后在新记录中补日期、准确对象、证据及剩余限制；不能直接把上述事项改成永久工程约束。
